数据规范:三个 JSONL + 复盘七字段

analysts.jsonl(每条论断一行):id / analyst / firm / layer / date / snapshot_id / claim / premise / falsifiable_by / tags / source_url / drive_file_id / status。schema 由 scripts/validate.py 强制,CI 拦截坏记录。

context_snapshots.jsonl(每周/每事件一条,被多条论断共享):关键宏观/市场数据 + narrative(必须当时写——数字事后能查,市场情绪查不回来)。环境快照独立成表:几年后可做「哪类环境下谁失灵」的横截面研究。

reviews.jsonl(论断到期复盘,七字段全部必填):outcome(hit/miss/partial+实际数字)· error_type(input=数据没料到可原谅 / framework=逻辑本身错要降权)· timing(leading/lagging)· missed_factors · key_references · my_action(我当时采纳/拒绝+关联 predict.py 预测)· lesson(一句话,作为权重调整依据)。

复盘三级:单条(到期触发)→ 季度批量(briefs/reviews/YYYY-QN.md)→ 半年面板评审(调权重、轮换面板)。存储:文本入 GitHub 永久保存;研报 PDF 入 Drive Analyst-Archive/(私有,合规),双向 drive_file_id 链接,年度 zip 备份双供应商冗余。
