## 修订二【Claude 修订】决策层（Phase 4）：从条件概率到组合动作

**插入位置**：原文"Phase Three / 第三阶段"之后，作为新增 Phase Four。

原文止步于"输出多个条件概率"。但概率不改变行为就没有价值。必须补一个**预先登记的决策映射层**，把状态向量映射到具体组合动作。设计原则有三：

1. **脆弱性塑造敞口，不做择时**。原文正确指出高估值可持续很久，因此决策层的动作是调整敞口形状（杠杆、对冲预算、再平衡带宽、现金缓冲），不是清仓/满仓开关。
2. **动作规则先于状态发生前写死**（与 predict.py 的预登记纪律同构），禁止在压力中临时发明规则。
3. **每档动作有成本预算**，尤其尾部对冲：预先规定年度对冲预算上限（如组合的 0.5–1.0%），防止"恐慌时买贵保险"。

示例决策映射表（具体阈值由使用者的规则系统 InvestOS 定义并回测）：

| 状态组合 | 组合动作（示例） |
|---|---|
| 估值脆弱性 > 90 分位，融资/保证金层正常 | 仅记录；新增买入改为分批；再平衡带宽收窄一档 |
| 估值高 + 集中度（HHI）历史高位 | 检查组合与 Top-10 重合度；等权/补充分散仓位比例上调 |
| 融资压力上升（repo/basis/dealer 指标恶化）且估值高 | 降杠杆一档；启用尾部对冲预算的 50%；现金缓冲提高 |
| 市场功能指标恶化（深度、fails、swap spread 异动） | 暂停所有非必要交易；只执行减风险动作；检查自身保证金链 |
| 官方 backstop 启用（SRF/swap line 用量跳升） | 不解读为"危机结束"信号；维持减风险状态直至融资指标回落 |
| 脆弱性全面回落 | 按预定阶梯恢复敞口，禁止一步复原 |

**决策层的复盘**与信号层分开：每次触发动作都在日志中记录"触发状态、执行动作、机会成本"，年度评估决策映射本身（误报成本是否可承受），这与原文的"每十年误报次数"指标直接对接。

## 修订三【Claude 修订】小样本统计诚实性声明

**插入位置**：原文"必须通过的验证协议"表格之前。

原文的验证协议（leave-one-crisis-out、calibration、PR-AUC）方法论正确，但有一层窗户纸必须捅破：**可用的系统性危机样本是个位数**（1987、1998、2000、2008、2020、2022-LDI，按定义不同 6–10 个）。这意味着：

- 原文推荐的含 V⊗S 交互项的 logit **在统计上不可估计**——参数远多于事件数。
- Calibration 测试（Brier、reliability diagram）在稀有事件 + 个位数样本下**没有统计功效**，通过测试不代表模型正确，未通过也不代表错误。
- Leave-one-crisis-out 的真实用途是**定性压力测试**（"该架构能否讲出 2008 的传导故事"），不是模型选择准则。

因此系统在可预见的未来应诚实定位为：**强先验的贝叶斯/阈值情景系统**。先验来自机制文献（原文引用的 Minsky/Borio/Brunnermeier 等），数据的作用是更新状态而不是估计结构参数。概率输出应表述为"基于先验框架的条件评估"，并与外部基准（OFR FSI、Fed FSR 定性评级、简单 term spread + EBP 模型）并排显示。自建系统的存在价值靠"相对基准的增量解释"逐年检验，而不是靠一次回测认证。
